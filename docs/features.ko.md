# Features

[English](features.md)

항목 상태는 `[ ]` 대기, `[~]` 진행 중, `[o]` 완료, `[!]` 보류, `[-]` 종료를 쓴다.
- [o] G1 — P0: git section이 git과 프로젝트의 저장소를 확인한다. 입력: clubhouse 팀원이 git worktree가 필요하고, 저장소가 아닌 프로젝트 폴더나 git이 없는 기기에는 저장소가 없다. 기대: plugin이 사이드바 section `git.status`를 제공하고, 사람이 settings의 sidebar set으로 이를 놓는다. Section이 보일 때와 `git.check`가 실행될 때 선언된 program `git --version`을 실행한다. git이 없으면 git이 없다고 보여 주고, 선언된 program으로 `xcode-select --install`을 실행하는 버튼 설치와 버튼 다시 확인을 보인다. git이 있고 프로젝트 루트가 work tree 안에 있지 않으면(`git rev-parse --is-inside-work-tree`), 폴더가 저장소가 아니라고 보여 주고 버튼 `git init`을 보인다. 이 버튼은 프로젝트 루트에서 `git init`을 실행하고 다시 확인한다. 그 밖에는 branch(`git branch --show-current`)를 보여 준다. Section은 모든 결과와 실패를 자기 page에 보여 주고, 각 실패를 `runtime.error`로 기록하며, status `git.state`를 공개한다([git section](spec/git.ko.md)). 코드로 완료: `ui/git-state.js`, `ui/status.js`, `ui/status.html`, `plugin.json`, `test/git-state.test.mjs`, `test/manifest-shape.test.mjs`. `test/git-state.test.mjs`의 `sectionView` Red/Green. core F1152(sections를 가진 plugin의 programs)가 필요하므로 engine 범위는 `^0.0.53`이다. 검증: F1152가 든 core build의 debug window에서, 저장소 밖 프로젝트 폴더는 git version과 버튼 `git init`, 다시 확인을 보였고 `git.state`는 `repository: "outside"`였다. Element `git.status.init`이 `.git`을 만들었고 section은 `브랜치: main`을, `git.state`는 `repository: "inside", branch: "main"`을 보였다. Slot과 다른 인자로 한 실행은 host의 거부를 section에 보였고 `workbench.record.error`로 기록되었다. 검사 기기에 git이 있으므로 `missing` 상태는 `versionState`와 `sectionView`의 test가 확인한다.
- [o] G2 — P0, G1 다음: 이 저장소가 plugin을 release해요. Workflow `ci.yml`과 `release.yml`이 push마다 `make`로 설치, test, 검사를 하고, 선언된 version의 tag가 없으면 release job이 plugin을 pack해요. 첫 version은 새 저장소의 시작 version인 0.0.1이에요. 원격에 `main`이 없으면 pre-push hook은 push하는 ref의 모든 commit을 검사해요. 빈 저장소에 하는 첫 push에는 `origin/main`이 없기 때문이에요. 확인: 로컬에서 `make test`와 `make check`가 통과해요.
- [o] G3 — P0: `status.html` page가 window theme의 색을 쓴다. Input: system appearance가 light인 상태에서 dark theme인 window. Behavior: dialog의 제목, label, button이 theme의 어두운 card 위 어두운 글자였다. View bridge는 theme의 card를 설정하는데, page는 글자, 선, 오류 색을 system color scheme에서 골랐기 때문이다. Expected: page는 view bridge가 root에 설정하는 theme token인 `--fg`에서 글자, `--edge`에서 선, `--fail`에서 오류 색을 쓰고(core docs/spec/native-surfaces.md, Theme), 자기 palette를 고르지 않는다. Red: `test/page-theme.test.mjs`의 test가 이전 page에서 실패했다. Green: 통과한다.
